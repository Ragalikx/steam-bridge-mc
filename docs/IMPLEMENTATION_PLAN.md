# Доводка перед ручным прогоном

Состояние на 29 октября 2026 года. Работа в локальной ветке `26.x`, переименованной из `main`. Изменения сохраняются локальными коммитами с авторством владельца; push не выполнялся. Dedicated остаётся вне текущего этапа. Panama используется для NeoForge 26.1/26.2/26.3 на Java 25, старые адаптеры сохраняют JNA. Основные пакеты сохраняют Windows natives; для Linux x64 добавлены четыре runtime-аддона по группам Java 8/17/21/25, покрывающие все поддерживаемые версии.

## Реализовано

- Общие core, TCP/Netty transport, lifecycle manager/client/server, социальные хранилища и JSON-конфигурация.
- Ограничения очередей и памяти, backpressure, отмена и повторное подключение, защита новой сессии от запоздавшей очистки старой.
- Собственные адаптеры Simple Voice Chat API и Plasmo API без включения их implementation в SBM. Глобальный UDP fallback сохранён для старого Simple Voice Chat.
- Voice handle допускается для разрешённой игровой Steam-сессии. Один peer занимает один voice handle; лимита в четыре участника в этом механизме нет.
- Регистрация адреса voice-сервиса учитывает владельца. Старый сервер и legacy socket не могут снять API-регистрацию нового сервера. Остановка Steam-host сохраняет адрес ещё работающего API voice-сервиса до его собственного закрытия.
- Ошибки загрузки и инициализации Steam обрабатываются с очисткой и возможностью повторной попытки. Ошибка cleanup не скрывает исходный отказ запуска.
- Один NeoForge 26.x JAR с тремя внутренними адаптерами и общим FFM backend. JNA и JNI bridge в него не включаются.
- В восьми GUI-адаптерах 1.16.5-1.21.1 добавлены точные привязки с runtime aliases. Сверены 104 поля, исправлены выбранный сервер, LAN-режим 1.16.5 и остановка при ошибке LAN publication. Подробности: `GUI_COMPATIBILITY.md`.
- В 26.x GUI заменён поиск по типу и порядку полей на именованные обращения. Отмена ConnectScreen меняет только `aborted`. Контракты полей и mixin hooks проверяются по трём настоящим Minecraft JAR.
- Независимый C/JNA ABI baseline и сверка с закреплённым снимком SDK 1.62. Проверяются также FFM/JNA сигнатуры, callbacks и configuration constants. Источник и ограничение original ZIP описаны в `STEAMWORKS_ABI.md`; зависимости закреплены по версиям и SHA-256.
- Сборщик 26.x явно задаёт DEFLATE level 9 для каждой записи, включая записи с собственным ZipInfo. Отладочные номера строк сохраняются.

- Linux Runtime для всех версий: четыре общих JAR по Java 8/17/21/25, Fabric preLaunch и Forge/FML/NeoForge wrappers, provider API 1, SHA-256 и проверка парных JNA natives. Для Panama сохранены четыре Linux ABI значения. Подробности и границы проверки: `LINUX_RUNTIME.md`.

## Автоматическая проверка

Общие тесты выполняются на Java 8/17/21, FFM и общий код также на Java 25. Проверяются локальные TCP/UDP, очереди, освобождение памяти, lifecycle, voice ownership и ошибки запуска. Настоящая Steam DLL проверяется без Steam initialization. Сборщик проверяет 12 Windows JAR, SHA-256, class-file targets, лицензии и состав native backend. Проверка mixin-контрактов не запускает Mixin transformer в Minecraft.

Итог: 127 тестов Java 25, по 113 на Java 8/17/21, без ошибок и пропусков. В предыдущем проходе восемь проверок логгера также прошли на Java 8 с Log4j API 2.0-beta9. Ранее обе скомпилированные реализации voice adapters прошли проверку по 13 голосовым JAR, включая девять для 26.x. Подробности: `VOICE_COMPATIBILITY.md`. Все 12 Windows JAR пересобраны и проверены, native smoke пройден для 11 старых пакетов. Размеры основных пакетов и четырёх runtime: dist/windows-x64/build-results.json. Проверены контракты runtime с API всех 11 старых загрузчиков; это не запуск Minecraft на Linux.

Результаты текущего прогона сохранены в `build/20261029-invites-results.json`, `build/20261029-invites-build.log`, `build/20261029-invites-native.log` и `dist/windows-x64/build-results.json`. ABI повторно сверено по 268 значениям и сигнатурам для Windows/Linux x64; проверки runtime сохранены в отдельных отчётах.

ABI используемых привязок сверено с закреплённым снимком SDK 1.62. Проверка оригинального ZIP Valve не выполнялась; источник и hashes приведены в `STEAMWORKS_ABI.md`.

## Исправления после аудита 25 октября

Исправлены null/empty receive, завершение входящей очереди при graceful close и cleanup duplicate pointers. При пустом активном соединении используется backoff 1/2/4 мс. Ошибка receive изолируется на затронутом мосту.

Оба backend используют общую TransportPolicy: send buffer 2 MiB, send-rate ceiling 8 MiB/s. Native pending/queue time проверяются отдельно для каждого моста. Добавлены строка очереди в управлении хостом, экспорт диагностики, проверки 32 локальных TCP-мостов и пяти мостов с одним LimitExceeded. Подробнее: [RELIABILITY.md](RELIABILITY.md).

По согласованию с владельцем Minecraft UUID сохраняется без изменений; внедрение SteamID-derived UUID и миграция playerdata исключены из текущего плана. SteamID сохраняет роль идентификатора доступа и владения игровой/голосовой сессией. Текущая матрица содержит 466 выполнений: по 113 на Java 8/17/21 и 127 на Java 25. Это не заменяет игровое подтверждение.

## Осталось до release

1. Проверить реальный Linux запуск с runtime-аддоном и связь Windows/Linux. Ubuntu native CI подготовлен, но ещё не выполнялся. Проверить запуск каждой заявленной Minecraft-интеграции, применение mixins, GUI и совместимость с модами меню. Для 26.x нужны все три запуска: 26.1, 26.2, 26.3.
2. Проверить настоящие Steam direct/Relay, повторный вход, отмену, закрытие мира, kick, остановку Steam, тяжёлый модпак и причины отключения по логам обеих сторон.
3. Проверить каждый voice-мод отдельно, включая его конкретные версии для 26.x, custom port, IPv6 bind, повторное открытие Steam-host и обычный IP-вход после Steam.
4. Провести многопользовательскую нагрузку с пятью и более участниками и медленным клиентом. Измерить задержки, throughput, память и GC. Автотесты не доказывают реальную ёмкость Steam или выигрыш производительности.
5. После одобрения владельца выполнить GitHub CI и проверить опубликованные checksums/attestations. Локальная генерация SHA-256 не подтверждает исполнение GitHub workflow.

Игровые проверки выполняются на итоговых dev-сборках. Найденные в игре ошибки потребуют повторения затронутых сценариев; гарантировать отсутствие такого повторного прогона нельзя.

## Чистка кода

После основного исправления транспорта удалены неиспользуемые методы и перегрузки, недостижимая ветка terminal-state, невостребованные поля snapshot и лишние голосовые счётчики. Общие типы импортируются явно. Подробности: [CODE_CLEANUP.md](CODE_CLEANUP.md). Сетевые лимиты и порядок доставки не менялись.

## Логирование

Штатные события перенесены на DEBUG, все адаптеры используют категорию Log4j `steambridge`. Предупреждения и ошибки фоновых циклов подавляют одинаковые повторы в течение 30 секунд и показывают их число в следующей записи. Отказы подключения содержат фазу и известный маршрут, ошибки моста содержат очереди. Ошибки запуска остаются ERROR. Порядок подключения и cleanup сохранён. Подробности: [LOGGING.md](LOGGING.md).

## Приглашения Steam, 29 октября

В управление сессией всех адаптеров добавлена кнопка отправки приглашения через Steam. Общий код публикует текущую сессию и проверяет принятое приглашение через Rich Presence; JNA и Panama обрабатывают callback. Подключение разрешено из главного меню и списка серверов, обычный login и доступ хоста сохраняются. Границы и ручные проверки двух аккаунтов: [STEAM_INVITES.md](STEAM_INVITES.md).
