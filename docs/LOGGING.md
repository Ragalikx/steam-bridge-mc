# Логирование SBM

Штатная инициализация, callback, вход в мир, остановка моста и сохранение диагностики пишутся на DEBUG. При обычном уровне INFO эти сообщения не заполняют консоль. Все адаптеры и общий транспорт используют категорию Log4j `steambridge`; библиотеки логирования в JAR не добавляются, API предоставляет Minecraft.

## Когда появляется предупреждение

WARN сообщает о восстановимой проблеме: отказе подключения, отклонении Minecraft login, ошибке локального TCP/UDP, исчерпании очереди, нарушении voice-интеграции, ошибке GUI/reflection или чтения настроек. Для отказа подключения выводятся фаза, handle, известный Steam-маршрут, native state и end reason. Ошибка TCP-моста содержит категорию закрытия и состояние очередей. Неизвестный маршрут отмечается как `unknown`.

Ошибки загрузки native-библиотек, Steam init и невозможность безопасно остановить native вызовы остаются ERROR. Сбой callback/receive loop тоже остаётся ERROR. Остановка Steam во время активной сессии даёт WARN; в простое это DEBUG. Существующие сообщения ошибок запуска сохраняют stack trace на ERROR.

## Повторы и подробности

Повторяющиеся предупреждения и ошибки фоновых циклов ограничены отдельно по типу события. Первая запись появляется сразу. Следующие 30 секунд одинаковое событие подавляется; очередная запись после этого окна содержит `suppressed=N`. Счётчик выводится при следующем событии, отдельного таймера и сообщения после прекращения ошибок нет.

Ограничитель хранит до 32 типов событий на экземпляр или класс. Ключи не содержат SteamID и не растут с числом игроков. Удаляется самый давно использованный ключ. Для времени используется `nanoTime`, обработка потокобезопасна. Это ограничивает только вывод сообщений, а не обработку пакетов, подключений или ошибок.

В предупреждениях через `ProblemLog` исключение представлено краткой причиной; полный stack trace доступен на DEBUG. Переводы строк и `${` в строковых аргументах нейтрализуются. Для подробного разбора включите DEBUG для категории `steambridge` в конфигурации логирования своего запуска Minecraft. Отдельной JSON-настройки логгера нет.

Нормальное закрытие уже остановленного клиента остаётся DEBUG. Отключение действующего клиента с экраном ошибки Minecraft остаётся WARN: по одному EOF нельзя достоверно определить намерение игрока. Сетевые состояния и порядок cleanup не меняются.

## Границы

Настройки глобального логирования не подменяются. Minecraft, загрузчик, другие моды и прямой вывод native Steam SDK в stderr управляются отдельно. DEBUG может включать идентификаторы Steam, локальные адреса и технические сведения, уже используемые диагностикой SBM.

Экспорт диагностики из интерфейса сохраняется. Автотесты проверяют окно подавления, счётчики, независимость событий, конкурентные вызовы, переполнение монотонных часов и формат причины ошибки. Сборка всех адаптеров проверяет совместимость вызовов логгера. Реальные причины отключения и порядок событий Minecraft дополнительно проверяются в игре.

Все 12 основных JAR и четыре Linux runtime собраны; GUI-контракты, состав JAR и SHA-256 проверены. Для 11 JNA-пакетов повторён native linkage smoke. Основные JAR выросли на 6,4–9,9 КБ из-за логгера и контекста ошибок; новых bundled-зависимостей нет. Отчёт: `build/20261028-logging-results.json`.
